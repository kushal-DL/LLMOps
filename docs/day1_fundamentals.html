The Big Picture

You've used ChatGPT. You've heard of GPT-4, Claude, Llama 3. But what's actually happening when you type a sentence and get a reply?

At its core, every large language model does exactly one thing: predict the most likely next token, given all the tokens that came before. Repeat that thousands of times and you get a paragraph. Do it well enough — across enough data — and it looks like intelligence.

Today we trace the full pipeline from the characters you type all the way to a probability distribution over the next word. Here's the journey at a glance:

Why TF32?

NVIDIA's TF32 is a 19-bit number format used for matrix multiplications on Ampere+ GPUs. It has the same exponent range as full FP32 (no overflow) but fewer mantissa bits — delivering roughly 3× throughput on A100 with negligible accuracy loss. Setting allow_tf32 = True is a free performance win.

Why set random seeds?

Neural networks start from random weights. Without a fixed seed, every run begins from a different point — making it impossible to compare experiments. We pin:

  • torch.manual_seed(42) — CPU operations (data loading, weight init)
  • torch.cuda.manual_seed_all(42) — all GPU operations

With the same seed, any two Day 2 training runs produce identical loss curves from step 1. That reproducibility is what lets you isolate the effect of a single change.

Tokenization

Neural networks work with numbers — floating-point vectors to be precise. But your input is text: characters. Tokenization bridges that gap: it converts raw text into a sequence of integer IDs that the model can process.

🔑
The tokenizer is NOT part of the model. It's a fixed lookup table trained once on a large corpus, then frozen. NanoLlama reuses GPT-2's tokenizer unchanged — no training needed.
Live Tokenization Demo
Input: "The transformer architecture changed everything."

Byte-Pair Encoding (BPE)

GPT-2 uses Byte-Pair Encoding — a data-driven algorithm that builds a vocabulary of variable-length subwords by iteratively merging the most common adjacent byte pairs in a training corpus:

  1. Start with every individual byte as its own token (256 items).
  2. Count all adjacent byte pairs across the corpus.
  3. Merge the most frequent pair into a new vocabulary entry.
  4. Repeat until the vocabulary reaches the target size — 50,257 for GPT-2.
BPE Merge Steps — "the transformer"
Characters start as individual tokens. Each step merges the most frequent pair.

Notice the Ġ prefix in the output: GPT-2 BPE treats " transformer" (space + word) as a different token from "transformer". This makes tokenization context-sensitive at word boundaries.

✅
BPE eliminates out-of-vocabulary. Because it can fall back to individual bytes, BPE can encode any Unicode input — no <unk> token needed. Every string is representable.

⚠️
Chunk size matters. Calling tokenizer.encode() on all 1.8M lines at once would build one enormous Python string in memory before tokenizing. Processing in 5,000-line chunks is a safe balance between speed and memory usage.

Sliding Window Dataset

How does a language model learn? By next-token prediction: given a sequence of tokens as input, predict what comes next. Every training step is just: "here's some text — what's the next word?"

One Example, Many Predictions

Given input [a, b, c, d], the model simultaneously predicts:

  • At position 0 (seeing only a): predict b
  • At position 1 (seeing a, b): predict c
  • At position 2 (seeing a, b, c): predict d

One sequence of length 4 gives 4 separate training signals in a single forward pass. Efficient!

Sliding Window — block_size=4, stride=2
Full token sequence (16 tokens). Blue = input x, Green = target y (x shifted by 1):
INPUT x (blue ↑)
—
TARGET y (green ↓) — x shifted by 1
—
Python — Notebook Cell 5
class SlidingWindowDataset(Dataset):
    def __init__(self, tokens, block_size=1024, stride=512):
        self.tokens     = tokens
        self.block_size = block_size
        self.starts     = list(range(0, len(tokens) - block_size - 1, stride))

    def __len__(self):
        return len(self.starts)

    def __getitem__(self, idx):
        s = self.starts[idx]
        x = self.tokens[s     : s + self.block_size]       # input
        y = self.tokens[s + 1 : s + self.block_size + 1]  # target = x shifted by 1
        return x, y

# NanoLlama v3 settings
block_size = 1024
train_ds   = SlidingWindowDataset(train_data, block_size=block_size, stride=512)
val_ds     = SlidingWindowDataset(val_data,   block_size=block_size, stride=512)

x0, y0 = train_ds[0]
print(f'x shape: {x0.shape}')   # → (1024,)
print(f'x[:4]  : {x0[:4].tolist()}')
print(f'y[:4]  : {y0[:4].tolist()} ← y is x shifted right by 1')
💡
Why stride=512 and not 1024? Overlapping windows (stride < block_size) give more training examples from the same data and train the model to handle any context position, not just clean non-overlapping chunks. The trade-off is correlation between adjacent batches — acceptable at NanoLlama's scale.

Token Embeddings

Token IDs are just integers: 464, 47385, 10959. As raw integers they have no geometric meaning — there's no sense in which 464 is "close to" 465 semantically. We need to convert them into vectors where distance reflects meaning.

An embedding table is a learned lookup matrix E of shape (vocab_size × d_model). To embed a token, we just index the right row:

E  ∈  ℝV × d   |   ei = E[token_idi]   |   V = 50,257  |  d = 512
Embedding Space — Semantic Clusters Emerge After Training
2D projection of 512-dimensional embedding vectors. At random init vectors are scattered; after training, semantic clusters form.
Python — Notebook Cell 6
n_embd = 512
emb    = nn.Embedding(vocab_size, n_embd)

param_count = vocab_size * n_embd
print(f'Embedding table: {vocab_size:,} × {n_embd} = {param_count:,} params')
# → 50,257 × 512 = 25,731,584 params
print(f'Memory (FP32):  {param_count * 4 / 1e6:.1f} MB')
# → 102.9 MB

sentence = 'The transformer architecture'
ids      = torch.tensor([tokenizer.encode(sentence)])   # (1, 3)

with torch.no_grad():
    vecs = emb(ids)   # (1, 3, 512)

print(f'vecs: {vecs.shape}')   # → torch.Size([1, 3, 512])

# Cosine similarity — near-zero at random init; clusters after training
for i in range(len(toks)):
    for j in range(i + 1, len(toks)):
        s = F.cosine_similarity(vecs[0, i:i+1], vecs[0, j:j+1], dim=-1).item()
        print(f'  {toks[i]!r} <-> {toks[j]!r}: {s:+.4f}')

Weight tying: NanoLlama uses the same matrix E for both input lookup and output scoring. The output logit for token v is computed as the dot product between the final hidden state and E[v]. This halves the parameter count for the largest tensor and provides useful regularisation.

No Positional Embedding Table

The original transformer (GPT-2) adds a separate learned positional embedding to each token position. NanoLlama replaces this with RoPE (Rotary Position Embeddings) — which injects position information directly inside the attention computation rather than adding it to the token vectors. You'll implement RoPE in Day 2.

Self-Attention

This is the mechanism that defines the transformer. Before attention, each position in a sequence was processed independently — a word had no direct way to "look at" other words. Self-attention fixes this: every token can attend to every other token.

The output at each position is a weighted blend of information from all positions, where the weights are learned from the content itself.

The Query, Key, Value Framework

Think of attention as a soft search engine:

Q
Query
"What am I looking for?" — Each token's search request
K
Key
"What do I offer?" — Each token's label that gets searched against
V
Value
"What do I actually contain?" — The information that gets retrieved

Q·Kᵀ measures how relevant each key is to each query — producing a score matrix. Softmax turns scores into weights (each row sums to 1). The output is a weighted sum of V: each token's representation is a mix of all values, weighted by relevance.

Attention(Q, K, V)  =  softmax( Q · Kᵀ / √dk ) · V
📐
Why divide by √dk? As embedding dimensions grow larger, dot products grow in magnitude proportionally, pushing softmax into a region with near-zero gradients (where one token dominates everything). Dividing by √dk keeps the variance of the dot products at ~1 regardless of dimension size.
Attention Weights — Which Tokens Each Position Attends To
Row = query token, Column = key token. Brighter = higher attention weight.

Causal Masking — Preventing Future Leakage

During training we feed the model a sequence and ask it to predict each next token simultaneously. But token at position 3 must not see token at position 4 (that's the answer we're asking it to predict). We enforce this with a lower-triangular causal mask:

Causal Mask — Every Token Can Only See Its Past
✓ = allowed   ✗ = masked to −∞ (→ 0 after softmax)
Lower triangle only. No peeking at the future.
The code:
mask = torch.tril(
  torch.ones(T, T)
).bool()

scores.masked_fill(
  ~mask,
  float('-inf')
)
# −∞ → 0 after softmax
Python — Notebook Cell 7: Scaled Dot-Product Attention
def scaled_dot_product_attention(Q, K, V, causal=True):
    """
    Q, K, V : (B, H, T, d_head)
    Returns  : output (B, H, T, d_head), weights (B, H, T, T)
    """
    B, H, T, d = Q.shape
    scale  = math.sqrt(d)
    scores = Q @ K.transpose(-2, -1) / scale   # (B, H, T, T)

    if causal:
        mask   = torch.tril(torch.ones(T, T, device=Q.device)).bool()
        scores = scores.masked_fill(~mask, float('-inf'))

    weights = torch.softmax(scores, dim=-1)   # rows sum to 1.0
    out     = weights @ V
    return out, weights


# ── Demo: 4 tokens, 2 heads, 8-dim head ─────────────────────
B, H, T, d = 1, 2, 4, 8
Q = torch.randn(B, H, T, d)
K = torch.randn(B, H, T, d)
V = torch.randn(B, H, T, d)

out, W = scaled_dot_product_attention(Q, K, V, causal=True)
print(f'Output : {out.shape}')    # → (1, 2, 4, 8)
print(f'Weights: {W.shape}')    # → (1, 2, 4, 4)

# Verify causal property: upper triangle must be exactly 0
print(f'Upper-tri sum (must be 0.0): {W[0,0].triu(1).sum().item()}')
🧠
What does the model actually learn to attend to? Different heads specialise: some track long-range subject-verb agreement, others handle co-reference ("it" → what "it" refers to), others track local syntax. This specialisation emerges purely from training — we don't program it.

Multi-Head Attention

Running attention once with the full d-dimensional space forces all heads to compete over the same representation. Multi-head attention runs H independent attention operations in parallel, each operating in a lower-dimensional subspace d/H, then concatenates their outputs:

MHA(x) = Concat(head1, head2, …, headH) · Wo    where headi = Attention(xWQi, xWKi, xWVi)
4 Heads × 16-dim each = 64-dim total
Input x — (B, T, 64)
↓ project to Q, K, V and split into H heads
↓ concatenate all heads → output projection Wo
Output — (B, T, 64) — same shape, each position enriched with context
Python — Notebook Cell 8: Multi-Head Attention
def multi_head_attention(x, W_q, W_k, W_v, W_o, n_head):
    """x: (B, T, C)  →  output: (B, T, C)"""
    B, T, C = x.shape
    d_head  = C // n_head

    def project_and_split(W):
        # Linear projection, then reshape C → n_head × d_head
        return W(x).view(B, T, n_head, d_head).transpose(1, 2)
        # → (B, n_head, T, d_head)

    Q = project_and_split(W_q)
    K = project_and_split(W_k)
    V = project_and_split(W_v)

    out, _ = scaled_dot_product_attention(Q, K, V, causal=True)

    # Merge heads: (B, n_head, T, d_head) → (B, T, C)
    out = out.transpose(1, 2).contiguous().view(B, T, C)
    return W_o(out)


C = 64; n_head = 4; B = 2; T = 6
W_q = nn.Linear(C, C, bias=False)
W_k = nn.Linear(C, C, bias=False)
W_v = nn.Linear(C, C, bias=False)
W_o = nn.Linear(C, C, bias=False)

x = torch.randn(B, T, C)
y = multi_head_attention(x, W_q, W_k, W_v, W_o, n_head)
print(f'Input : {x.shape}')   # → (2, 6, 64)
print(f'Output: {y.shape}')   # → (2, 6, 64) — same shape
print(f'Heads : {n_head} × {C // n_head}-dim')
🔭
Day 2 upgrade: Grouped Query Attention (GQA). NanoLlama uses 8 query heads but only 4 key-value pairs — each KV pair is shared by 2 query heads. This halves KV-cache memory at inference with negligible quality loss. Used in Llama 2, Mistral, and most modern models.
