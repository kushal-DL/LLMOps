class SlidingWindowDataset(Dataset):
    def __init__(self, tokens, block_size=1024, stride=512):
        self.tokens     = tokens
        self.block_size = block_size
        self.starts     = list(range(0, len(tokens) - block_size - 1, stride))

    def __getitem__(self, idx):
        s = self.starts[idx]
        return self.tokens[s : s + self.block_size], \
               self.tokens[s+1 : s + self.block_size + 1]

RMSNorm

Normalisation layers stabilise training by rescaling activations at each layer. The original Transformer used LayerNorm. Modern LLMs (Llama 1/2/3, Mistral, Qwen, Gemma, DeepSeek) replace it with the simpler RMSNorm.

LayerNorm

μ = (1/d) Σ xᵢ
σ = √( (1/d) Σ (xᵢ−μ)² + ε )

LN(x) = (x − μ) / σ · γ + β
RMSNorm

RMS(x) = √( (1/d) Σ xᵢ² + ε )

RN(x) = x / RMS(x) · γ
Step-by-step comparison

LayerNorm — 4 steps

1 Compute mean μ
2 Subtract mean (x−μ)
3 Compute std σ
4 Divide by σ
5 Scale γ + shift β

RMSNorm — 2 steps

1 Compute RMS
2 Divide by RMS
3 Scale γ only
✓ No mean compute   ✓ No β parameter
Python — RMSNorm
class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(dim))
        self.eps    = eps

    def forward(self, x):
        # cast to float32 before squaring — prevents overflow in fp16
        norm = x.float().pow(2).mean(-1, keepdim=True).add(self.eps).rsqrt()
        return (x.float() * norm).type_as(x) * self.weight
💡
RMSNorm has 512 parameters (γ only) vs LayerNorm's 1024 parameters (γ + β). With 17 norm layers in the model (2 per block × 8 blocks + 1 final), that's 8,704 fewer parameters — small in absolute terms but reflects a principled simplification: mean-centring contributes almost nothing to representation quality.

RoPE: Rotary Position Embeddings

GPT-2 adds a learned position embedding table to token embeddings before the first block — each absolute position 0, 1, 2 … gets a different 512-dim vector, learned during training. This has two problems: (1) attention patterns depend on absolute position, not relative distance, and (2) you can't use the model beyond the training context length without re-training.

RoPE (Su et al., 2021) takes a different approach: instead of adding position information to the token embedding, it rotates the Query and Key vectors inside every attention layer. The rotation angle depends on position. Because the attention score is Q·Kᵀ, and a dot product of two rotated vectors naturally depends only on the angle between them (i.e. relative position), the model learns relative position encoding for free — with zero extra parameters.

The core idea: rotate q at position m by angle mθ, k at position n by nθ

q'ₘ = qₘ · eimθ     k'ₙ = kₙ · einθ

q'ₘ · k'ₙ = qₘ · kₙ · ei(m−n)θ  →  depends only on (m−n)

For real-valued vectors, complex rotation becomes a 2D rotation applied to consecutive dimension pairs:

rotate_half(x) = [−x₂, x₁]    (swap halves, negate first)

x' = x·cos(mθ) + rotate_half(x)·sin(mθ)

Frequencies: θᵢ = rope_theta−2i/d    (geometric decrease)
RoPE — Position Encoded as Rotation Angle

Each position gets a different rotation angle.

Position 0: 0°
Position 1: θ
Position 2: 2θ
Position 3: 3θ

When you compute q·k across positions,
only the difference in angle matters.

✓ Zero extra parameters
✓ Relative position by construction
✓ Generalises to longer sequences

Python — RoPE implementation
def rotate_half(x):
    """Swap the two halves of last dim and negate first half."""
    x1 = x[..., : x.shape[-1] // 2]
    x2 = x[..., x.shape[-1] // 2 :]
    return torch.cat([-x2, x1], dim=-1)

def apply_rotary_emb(q, k, cos, sin):
    cos = cos.unsqueeze(0).unsqueeze(0)   # (1, 1, T, head_dim)
    sin = sin.unsqueeze(0).unsqueeze(0)
    q_rot = (q * cos) + (rotate_half(q) * sin)
    k_rot = (k * cos) + (rotate_half(k) * sin)
    return q_rot, k_rot

# Precompute sin/cos table (done once in NanoLlama.__init__)
head_dim = config.n_embd // config.n_head   # 512 / 8 = 64
freqs    = 1.0 / (config.rope_theta ** (
    torch.arange(0, head_dim, 2).float() / head_dim
))                                           # (head_dim/2,)
t     = torch.arange(config.block_size, dtype=torch.float32)
freqs = torch.outer(t, freqs)             # (block_size, head_dim/2)

rope_cos = torch.cat([freqs.cos(), freqs.cos()], dim=-1)   # (T, head_dim)
rope_sin = torch.cat([freqs.sin(), freqs.sin()], dim=-1)
💡
Rotation preserves vector norms — only direction changes, not magnitude. This means RoPE doesn't distort the scale of Q and K, keeping attention scores well-scaled. The frequency schedule θᵢ = rope_theta^(−2i/d) gives fine-grained position information at low-index dimensions and coarse structure at high-index dimensions.

Grouped Query Attention (GQA)

At inference time, autoregressive generation requires the model to look back at all previous tokens on every step. The Key and Value tensors for all previous positions must be stored in GPU memory — this is the KV-cache. For long contexts, the KV-cache dominates memory consumption, not the model weights.

Standard Multi-Head Attention (MHA) has equal numbers of Q, K, V heads — so the KV-cache grows linearly with the number of heads. GQA (Ainslie et al., 2023) uses fewer KV heads than Q heads. Multiple Q heads share a single KV head pair:

The repeat_kv function expands 4 KV heads back to 8 before the attention dot-product using a view + expand trick (no memory copy):

Python — GQA
def repeat_kv(x, n_rep):
    """Expand KV heads to match Q count. No memory copy via expand()."""
    if n_rep == 1:
        return x
    B, n_kv, T, D = x.shape
    x = x[:, :, None, :, :].expand(B, n_kv, n_rep, T, D)
    return x.reshape(B, n_kv * n_rep, T, D)


class GQAttention(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.n_rep    = config.n_head // config.n_kv_head   # = 2
        self.head_dim = config.n_embd // config.n_head       # = 64

        # Separate Q / KV projections — bias=False (Llama convention)
        self.q_proj = nn.Linear(config.n_embd, config.n_head    * self.head_dim, bias=False)
        self.k_proj = nn.Linear(config.n_embd, config.n_kv_head * self.head_dim, bias=False)
        self.v_proj = nn.Linear(config.n_embd, config.n_kv_head * self.head_dim, bias=False)
        self.o_proj = nn.Linear(config.n_embd, config.n_embd, bias=False)

    def forward(self, x, cos, sin):
        B, T, C = x.shape
        q = self.q_proj(x).view(B, T, self.n_head,    self.head_dim).transpose(1, 2)
        k = self.k_proj(x).view(B, T, self.n_kv_head, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).view(B, T, self.n_kv_head, self.head_dim).transpose(1, 2)

        q, k = apply_rotary_emb(q, k, cos, sin)  # inject position via RoPE
        k    = repeat_kv(k, self.n_rep)           # (B, n_head, T, head_dim)
        v    = repeat_kv(v, self.n_rep)

        att = (q @ k.transpose(-2, -1)) / math.sqrt(self.head_dim)
        att = att.masked_fill(self.mask[:, :, :T, :T] == 0, float('-inf'))
        return self.resid_drop(self.o_proj(
            (F.softmax(att, dim=-1) @ v).transpose(1,2).contiguous().view(B, T, C)
        ))

SwiGLU: Gated Feed-Forward Network

The feed-forward sublayer in GPT-2 is a two-layer MLP with GELU activation. SwiGLU (Shazeer, 2020) replaces this with a gated variant where one branch controls how much of the other branch's signal passes through.

GPT-2 FFN

FFN(x) = W₂ · GELU(W₁x)
SwiGLU

SwiGLU(x) = W_down · (SiLU(W_gate·x) ⊙ W_up·x)
SiLU(x) = x · σ(x)

Python — SwiGLU
class SwiGLU(nn.Module):
    def __init__(self, config):
        super().__init__()
        hidden = config.intermediate_size   # 1536
        self.gate_proj = nn.Linear(config.n_embd, hidden, bias=False)
        self.up_proj   = nn.Linear(config.n_embd, hidden, bias=False)
        self.down_proj = nn.Linear(hidden, config.n_embd, bias=False)
        self.drop      = nn.Dropout(config.dropout)

    def forward(self, x):
        return self.drop(
            self.down_proj(
                F.silu(self.gate_proj(x)) * self.up_proj(x)
            )
        )

Transformer Block

A transformer block applies attention and FFN in sequence, each wrapped in a residual connection. NanoLlama uses the pre-norm pattern: normalise the input before each sublayer (not after).

Key idea: the residual skip-connections (the + boxes) always add the original signal back. Even if a sublayer produces noisy gradients, the skip ensures the signal flows cleanly through.

Pre-norm vs post-norm

The original "Attention is All You Need" Transformer used post-norm: apply normalisation after the residual add. This can produce large gradient magnitudes at early layers, requiring careful initialisation and learning-rate warmup.

Pre-norm keeps the residual stream clean — the skip connection always carries the unnormalised signal, which stabilises training and allows deeper networks without gradient instability.

Python — TransformerBlock
class TransformerBlock(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.attn_norm = RMSNorm(config.n_embd)
        self.attn      = GQAttention(config)
        self.ffn_norm  = RMSNorm(config.n_embd)
        self.ffn       = SwiGLU(config)

    def forward(self, x, cos, sin):
        x = x + self.attn(self.attn_norm(x), cos, sin)   # pre-norm + residual
        x = x + self.ffn(self.ffn_norm(x))               # pre-norm + residual
        return x

Weight initialisation

All linear and embedding weights are initialised with N(0, 0.02) — the same scheme GPT-2 uses. No bias terms anywhere (bias=False in all linears), matching Llama convention.

Autoregressive generation

During inference, generate() samples one token at a time. Two controls shape the distribution:

  • Temperature T: divides logits by T before softmax. T → 0 = greedy (argmax); T → ∞ = uniform random.
  • Top-k: zeroes out all logits except the k highest before sampling. Prevents sampling from the long tail of near-zero probability tokens.
Python — NanoLlama (key methods)
class NanoLlama(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.tok_emb = nn.Embedding(config.vocab_size, config.n_embd)
        self.drop    = nn.Dropout(config.dropout)
        self.blocks  = nn.ModuleList([TransformerBlock(config)
                                       for _ in range(config.n_layer)])
        self.norm = RMSNorm(config.n_embd)
        self.head = nn.Linear(config.n_embd, config.vocab_size, bias=False)
        self.head.weight = self.tok_emb.weight   # ← weight tying (saves 25.7M params)

        # RoPE tables as buffers — auto-move to device with .to(device)
        self.register_buffer('rope_cos', ...)
        self.register_buffer('rope_sin', ...)
        self.apply(self._init_weights)

    def forward(self, idx, targets=None):
        x   = self.drop(self.tok_emb(idx))
        cos = self.rope_cos[:idx.shape[1]]
        sin = self.rope_sin[:idx.shape[1]]
        for block in self.blocks:
            x = block(x, cos, sin)
        logits = self.head(self.norm(x))
        loss   = F.cross_entropy(logits.view(-1, logits.size(-1)),
                                   targets.view(-1)) if targets is not None else None
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, max_new_tokens=200, temperature=0.8, top_k=50):
        self.eval()
        for _ in range(max_new_tokens):
            idx_cond = idx[:, -self.config.block_size:]
            logits, _ = self(idx_cond)
            logits    = logits[:, -1, :] / temperature       # temperature scaling
            if top_k:
                v, _ = torch.topk(logits, top_k)
                logits[logits < v[:, [-1]]] = float('-inf')  # zero out tail
            idx = torch.cat([idx, torch.multinomial(F.softmax(logits,-1), 1)], dim=1)
        return idx

Automatic Mixed Precision (AMP)

AMP runs the forward and backward passes in FP16 (faster matrix multiplies, half the memory) while keeping a master copy of weights in FP32 for the optimizer update. GradScaler multiplies the loss by a large constant before backward, then divides the gradients back — this prevents FP16 underflow in small gradients.

Python — Optimizer + LR + AMP
optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=max_lr, betas=(0.9, 0.95), weight_decay=0.1
)

def get_lr(step):
    if step < warmup_steps:
        return max_lr * (step + 1) / warmup_steps
    ratio = (step - warmup_steps) / max(1, max_steps - warmup_steps)
    return min_lr + 0.5 * (max_lr - min_lr) * (1.0 + math.cos(math.pi * ratio))

scaler = torch.amp.GradScaler('cuda', enabled=use_amp)

We estimate loss on eval_iters=20 batches from each split rather than the full dataset — fast enough to run every 200 training steps without dominating wall-clock time.

Python — estimate_loss()
@torch.no_grad()
def estimate_loss():
    model.eval()   # disables dropout for stable estimate
    out = {}
    for split_name, loader in [('train', train_loader), ('val', val_loader)]:
        losses    = []
        data_iter = iter(loader)
        for _ in range(eval_iters):
            xb, yb = next(data_iter)
            with autocast_ctx():
                _, loss = model(xb.to(device), yb.to(device))
            losses.append(loss.mean().item())
        out[split_name] = sum(losses) / len(losses)
    model.train()   # re-enable dropout
    return out
ℹ️
model.eval() disables dropout during evaluation — otherwise each forward pass would produce slightly different loss values, making your metrics noisy. model.train() re-enables it afterwards. Using @torch.no_grad() skips gradient computation, halving the memory cost and speeding up the eval pass.

Training Loop

The training loop follows the standard recipe for transformers. Each step has 6 operations in a specific order — the order matters because GradScaler modifies gradients between backward and the optimizer step.

6-Step Inner Loop
  1. Set LR — update all param groups to get_lr(step)
  2. Forward pass — under AMP autocast (FP16)
  3. Scale + backward — scaler.scale(loss).backward()
  4. Unscale + clip — scaler.unscale_(optimizer) then clip_grad_norm_(..., 1.0)
  5. Optimizer step — scaler.step(optimizer)
  6. Scaler update — adjusts scale factor for next step
Python — Training Loop
while step < max_steps:
    for xb, yb in train_loader:
        if step >= max_steps: break

        # 1. Set LR for this step
        lr = get_lr(step)
        for pg in optimizer.param_groups: pg['lr'] = lr

        xb, yb = xb.to(device), yb.to(device)
        optimizer.zero_grad(set_to_none=True)

        # 2. Forward under AMP
        with autocast_ctx():
            _, loss = model(xb, yb)

        # 3. Scale loss + backward
        scaler.scale(loss.mean()).backward()

        # 4. Unscale + clip gradients
        scaler.unscale_(optimizer)
        torch.nn.utils.clip_grad_norm_(model.parameters(), grad_clip)

        # 5+6. Optimizer step + scaler update
        scaler.step(optimizer)
        scaler.update()

        if step % eval_interval == 0:
            losses = estimate_loss()
            ppl    = math.exp(min(losses['val'], 20))
            print(f'step {step} | val {losses["val"]:.4f} | ppl {ppl:.1f}')
        step += 1

Gradient clipping

clip_grad_norm_(model.parameters(), 1.0) computes the global L2 norm of all gradients and, if it exceeds 1.0, rescales the entire gradient vector. This prevents rare explosive gradient steps — common when a training batch happens to produce an unusually large loss signal.

Text Generation

After training, generate() samples tokens autoregressively. Two sampling hyperparameters control the quality-diversity tradeoff:

T < 1
Sharp distribution
Predictable, repetitive
T = 0.8
Balanced
Creative but coherent
T > 1
Flat distribution
Surprising, sometimes incoherent
Temperature Effect on Token Distribution
0.80
Low temperature concentrates probability on top tokens. High temperature spreads it across the vocabulary.
Python — generation examples
prompts = [
    'The history of artificial intelligence began',
    'The scientist carefully examined the results and',
    'Once upon a time in a kingdom far away,',
]

for prompt in prompts:
    input_ids  = tokenizer.encode(prompt)
    x          = torch.tensor([input_ids]).to(device)
    output_ids = raw_model.generate(x, max_new_tokens=150,
                                        temperature=0.8, top_k=50)
    print(tokenizer.decode(output_ids[0].tolist()))

Day 3 Preview: Fine-tuning Ops

Tomorrow you apply LoRA (Low-Rank Adaptation) to fine-tune a Gemma 2B model on a downstream task. Instead of updating all 2 billion parameters, LoRA injects small trainable rank-decomposition matrices into attention layers:

  • LoRA: W' = W + BA where B ∈ ℝd×r, A ∈ ℝr×k, r ≪ d
  • Fine-tune with 100× fewer parameters than full fine-tuning
  • Base model weights stay frozen — no catastrophic forgetting
  • Multiple LoRA adapters can be swapped onto the same base model
